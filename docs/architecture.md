# MCP 기반 3D 아바타 대화 앱 서버 구조

## 웹 애플리케이션 서버 구조도 개요

제시된 웹 애플리케이션은 사용자가 업로드한 3D 아바타를 웹 브라우저에서 렌더링하고, 사용자의 입력(텍스트)을 LLM(대규모 언어 모델)으로 전달하여 아바타의 행동(표정, 시선, 움직임 등)과 텍스트 응답을 받는 상호작용을 목표로 합니다. 이를 위해 서버는 VRM 파일 관리, LLM과의 간접적인 연동, 그리고 아바타 제어를 위한 도구 노출이라는 세 가지 핵심 역할을 수행해야 합니다.
여기서는 Model Context Protocol (MCP)의 클라이언트-호스트-서버 아키텍처 [1, 2]를 활용하여, 웹 브라우저가 MCP의 '호스트'이자 '클라이언트' 역할을 수행하고, 당신의 백엔드 서버가 'MCP 서버' 역할을 수행하는 형태로 설계할 수 있습니다.

## 주요 구성 요소 및 역할

1. 웹 브라우저 (클라이언트 측 - MCP 호스트 및 클라이언트 역할)
   사용자가 직접 상호작용하는 웹 애플리케이션의 프론트엔드입니다.
   • 프론트엔드 UI: 사용자가 3D 아바타를 볼 수 있는 캔버스, 채팅 입력 필드 및 응답 표시 영역, VRM 파일 업로드 버튼, LLM API 경로 입력 필드 등으로 구성됩니다.
   • VRM 로더 및 렌더러: three.js 라이브러리와 VRMLoaderPlugin [3, 4]을 사용하여 사용자가 업로드한 .vrm 파일을 웹 브라우저에 불러오고 3D로 렌더링합니다. 이 플러그인은 VRM 파일을 three.js가 이해할 수 있는 형태로 변환합니다 [3].
   • VRM 제어 로직: 렌더링된 VRM 모델의 다양한 기능을 제어합니다 [5]. 예를 들어, 표정 관리자 (VRMExpressionManager) [6]를 통해 웃거나 화내는 표정을 설정하고, 시선 추적 시스템 (VRMLookAt) [7]으로 아바타의 눈과 머리가 특정 대상을 바라보게 하며, 휴머노이드 시스템 (VRMHumanoid) [8]으로 뼈대 기반의 움직임을 제어할 수 있습니다. 머리카락이나 옷자락의 자연스러운 물리 효과는 스프링본 물리 시스템 (VRMSpringBone) [9]으로 구현됩니다.
   • MCP 클라이언트 라이브러리 (JavaScript): 당신의 백엔드 서버에서 구현된 MCP 서버와 JSON-RPC 2.0 기반 메시지 [10-12]를 통해 통신하는 역할을 합니다. 또한, LLM과의 실제 상호작용을 담당합니다. MCP 프로토콜은 stdio와 Streamable HTTP 두 가지 표준 전송 메커니즘을 지원하는데 [13], 웹 환경에서는 Streamable HTTP [14]가 적합합니다.
2. 당신의 웹 애플리케이션 백엔드 서버 (서버 측 - MCP 서버 역할)
   실제 비즈니스 로직과 아바타-LLM 연동의 핵심이 되는 서버입니다.
   • API 게이트웨이 / 웹 서버:
   ◦ 웹 브라우저에 정적 프론트엔드 파일(HTML, CSS, JavaScript)을 제공합니다.
   ◦ 사용자의 VRM 파일 업로드 요청을 처리하고, 저장된 VRM 파일을 브라우저로 다시 제공하는 RESTful API 엔드포인트를 제공합니다.
   ◦ 웹 브라우저의 MCP 클라이언트와 통신하기 위한 MCP HTTP 엔드포인트 [15] 역할을 합니다. 이 엔드포인트는 JSON-RPC 요청을 수신하고 응답합니다 [10].
   • VRM 파일 스토리지: 사용자가 업로드한 .vrm 파일을 안전하게 저장하는 공간입니다. 파일 시스템이나 클라우드 스토리지 서비스(예: AWS S3)를 사용할 수 있습니다.
   • MCP 서버 애플리케이션 로직:
   ◦ 아바타 제어 도구 정의 (Tools): MCP 서버는 아바타의 특정 행동을 제어하는 "도구(Tools)"를 정의하고 노출합니다 [16, 17]. 예를 들어, 다음과 같은 도구를 포함할 수 있습니다: _ set_expression(expression_name, weight): 특정 표정(happy, angry 등)을 설정 [6]. _ look*at(target_position_x, target_position_y, target_position_z): 아바타의 시선을 특정 3D 좌표로 유도 [7]. * set*pose(bone_name, rotation_x, rotation_y, rotation_z): 아바타의 특정 뼈대 회전을 조작하여 자세를 변경 [8]. * play*animation(animation_id): 미리 정의된 애니메이션을 재생 [18]. 이러한 도구들은 JSON 스키마를 통해 입력 및 예상 출력 구조를 정의합니다 [19, 20].
   ◦ LLM 연동 로직: * 사용자의 채팅 입력이 웹 브라우저의 MCP 클라이언트를 통해 MCP 서버로 전달됩니다. _ MCP 서버는 이 입력을 바탕으로 LLM에게 질의할 메시지(messages)를 구성하고, MCP 클라이언트의 sampling/createMessage 요청 [21, 22]을 호출합니다. 이는 서버가 LLM SDK를 직접 통합하지 않고도 클라이언트를 통해 LLM 기능을 활용할 수 있게 합니다 [23]. _ LLM으로부터의 응답을 MCP 클라이언트로부터 수신합니다. LLM의 응답은 단순 텍스트일 수도 있고, 정의된 도구를 호출하라는 지시(예: "아바타가 웃는 표정을 짓게 해줘")를 포함할 수도 있습니다 [24]. \_ LLM 응답에 도구 호출 지시가 포함되어 있다면, MCP 서버는 해당 도구(set_expression 등)를 실행하고, 그 결과를 다시 웹 브라우저의 MCP 클라이언트로 전달합니다 [24].
   ◦ 서버 역량 선언: MCP 서버는 초기화(initialize) 단계에서 자신이 제공하는 tools 역량(capability)을 클라이언트에 선언해야 합니다 [25, 26].
   ◦ 로깅: MCP 서버는 MCP 로깅 프로토콜 [27]을 사용하여 클라이언트(웹 브라우저 콘솔 등)로 구조화된 로그 메시지를 전송할 수 있습니다. 이는 서버 내부 동작을 디버깅하고 모니터링하는 데 유용합니다 [28].
3. 외부 LLM 서비스 (사용자가 API 경로를 제공)
   이것은 당신의 웹 애플리케이션 외부에 존재하는 LLM 제공자의 API입니다 (예: Anthropic Claude API).
   • 사용자가 제공한 API 경로를 통해 웹 브라우저의 MCP 클라이언트가 직접 HTTP 요청을 보냅니다.
   • LLM은 사용자의 질의와 (필요하다면) 대화 맥락을 기반으로 응답을 생성하며, 아바타 행동을 위한 도구 호출 지시를 포함할 수 있습니다.

## 상호작용 흐름 예시

1. 아바타 업로드 및 렌더링: 사용자가 VRM 파일을 업로드하면, 백엔드 서버의 API 게이트웨이가 이를 받아 VRM 파일 스토리지에 저장하고, 브라우저의 프론트엔드 UI는 해당 파일을 요청하여 VRM 로더 및 렌더러를 통해 화면에 아바타를 표시합니다.
2. LLM API 경로 설정: 사용자가 외부 LLM 서비스의 API 경로를 입력하면, 이 정보는 웹 브라우저의 MCP 클라이언트가 LLM과 통신하는 데 사용됩니다.
3. 사용자 대화 시작: 사용자가 채팅창에 메시지를 입력합니다.
4. LLM 질의: 웹 브라우저의 MCP 클라이언트는 사용자 메시지를 받아 백엔드 서버의 MCP 서버 애플리케이션 로직으로 전달합니다. MCP 서버는 이를 바탕으로 LLM에게 질의할 sampling/createMessage 요청을 구성하고, 다시 MCP 클라이언트로 sampling/createMessage 요청을 보냅니다 [21].
5. LLM 응답 수신: MCP 클라이언트는 이 sampling/createMessage 요청을 받아 사용자가 지정한 외부 LLM 서비스로 실제 API 호출을 수행합니다. LLM 서비스는 텍스트 응답과 함께, 예를 들어 "아바타를 웃게 해"와 같은 도구 호출 지시를 포함한 응답을 반환할 수 있습니다.
6. 아바타 제어: MCP 클라이언트가 LLM 응답을 받으면, 만약 도구 호출 지시(tool_use [24])가 있다면 이를 백엔드 MCP 서버 애플리케이션 로직으로 tools/call 요청을 보냅니다 [24].
7. 도구 실행 및 프론트엔드 전달: MCP 서버 애플리케이션 로직은 tools/call 요청을 처리하고, 해당 아바타 제어 도구(예: set_expression)를 실행합니다. 이 도구는 아바타에 적용할 최종 명령(예: expression_name: "happy", weight: 1.0)을 웹 브라우저의 VRM 제어 로직으로 전달하기 위해 다시 MCP 클라이언트로 전달합니다 (MCP 프로토콜 메시지를 통해).
8. 아바타 업데이트 및 텍스트 표시: 웹 브라우저의 VRM 제어 로직은 수신된 명령에 따라 3D 아바타의 표정을 변경하고, LLM의 텍스트 응답은 프론트엔드 UI에 표시됩니다.
9. 인간 개입: MCP 샘플링 [29] 및 도구 사용 [30, 31]에는 "인간의 개입(human-in-the-loop)" 원칙이 적용되어, 사용자가 LLM 요청을 검토하고 승인/거부할 수 있는 UI를 제공해야 합니다.
